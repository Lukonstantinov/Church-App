# Church Youth App — notes for Claude

A Telegram bot + Mini App for a church's youth ministries: members, meetings with roll
call, events, posts, money, reminders and reports. Runs free on Cloudflare (Workers + D1).
Full design: `docs/PLAN.md`. Setup and deploy: `README.md`.

The owner is a non-professional developer who tests on a phone inside Telegram. Explain
results in plain language, recommend one approach, and keep UI polished (light + dark).

## Layout

```
apps/worker     Cloudflare Worker (Hono): REST API /api, bot webhook /bot, /media, cron jobs
  src/api/        routes (meetings.ts, events.ts, groups.ts, treasury.ts, church.ts …)
  src/lib/        logic (meetings, events, eventReminder, liveNotice, meetingHelpers,
                  meetingAnnounce, meetingNotify, outbox, looks, media …)
  src/jobs/tick.ts  cron: every 5 min (live notices, event reminders, send outbox),
                  hourly (generate scheduled meetings, roll-call nudges, housekeeping)
  src/bot/bot.ts  bot commands and inline-button callbacks
  src/db/schema.ts  Drizzle schema; migrations/ generated by drizzle-kit
  test/           vitest in the Workers pool (real D1, Telegram mocked)
apps/webapp     React + Vite + Tailwind 4 Mini App (served by the Worker as static assets)
  src/screens/    one file per screen; src/components/ shared UI; src/lib/ hooks/helpers
  src/lib/queries.ts  all API hooks (TanStack Query); src/lib/nav.tsx  routes/stack
  src/lib/guide.ts    in-app developer Instructions (keep in step with this file)
packages/shared Types, zod schemas, i18n (ru = reference, en, lt), formatting, permissions
```

## Commands (run before every push)

```sh
pnpm install
pnpm typecheck && pnpm lint && pnpm format:check && pnpm test && pnpm build
pnpm format                      # fix formatting
cd apps/worker && npx drizzle-kit generate --name <change>   # after editing schema.ts
```

Deploy: push to `master` → staging (CI applies migrations). Production: GitHub Actions →
Deploy → Run workflow → production.

## Conventions

- **i18n:** every UI/bot string lives in `packages/shared/src/i18n/ru.ts` (the `Messages`
  type comes from it); add the same key to `en.ts` and `lt.ts`. Bot strings are HTML —
  escape values with `escapeHtml`.
- **Migrations:** never hand-write `migrations/meta/*`; generate with drizzle-kit. Data
  fixes may be appended to the generated SQL after `--> statement-breakpoint`.
- **Bot messages** go through the outbox (`enqueue` + `drainOutbox`), with a `dedupeKey`
  so a job never sends twice; also record an in-app notification (`recordNotification`).
- **Media** is stored in D1 and served via signed URLs (`signedMediaUrl(secret, id)`);
  pass `c.env.WEBHOOK_SECRET` where rows need picture links (e.g. `toMeetingRows`).
- **Permissions:** positions grant rights (`packages/shared/src/permissions.ts`); church
  admins have all. Developer = admin whose Telegram ID is in `ADMIN_TELEGRAM_IDS`.
- Comments explain _why_ in plain sentences; match the existing style and density.
- Respect `html[data-motion]` (off / calm / lively) and `prefers-reduced-motion` for
  animations; colours via CSS vars (`--brand`, `--brand-partner`), both themes.
- New public worker paths outside `/api`, `/bot`, `/media` must be added to
  `assets.run_worker_first` in `apps/worker/wrangler.jsonc`.

## What the app does (feature map)

**Church & ministries** — church settings (name, colour, logo = "main photo", language,
time zone, poster label, main-window background); ministries ("environments") with own
look (colour, pattern, logo, photo), background, default place, Telegram chat; archive.

**People** — invite link/QR via the bot, join approval, offline members with claim codes,
positions with rights, labels, contacts, person photos (`users.photo_media_id`).

**Meetings** — one-off, repeating series (weekly / biweekly / monthly, all dates created
at once: `meetings.series_id`, `repeat_rule`; edits can apply to the rest of the series),
and weekly schedules generated by cron. Chosen-people audience. Poster designed like an
event cover (`meetings.design`, `template_id`) with up to 4 speakers (`speakers` JSON); layout classic or a collage of
speakers' photos (`design.posterLayout`, also for events).
People block (ministry background or a photo, card colour: `meetings.people_look`): leader,
speakers (`meeting_helpers.speaker`, 🎤, listed first and used on the poster when it has no
speakers of its own), snacks (optional), other services with icons; services are saved per
ministry (`groups.meeting_services`) and added via "+". Each person is asked by bot with
Agree / Can't; card/chip style dark / glass / colour / mixed tints and role icons
(`people_look`), chips on home meeting cards (`TeamChips`), "who serves" message
(`lib/meetingRoster.ts`, also in announcements); marks ✓ / ✗ (`*_declined_by`, `declined_at`) / waiting. Announce,
time-changed and cancelled notices with "Will you come?" answers. Roll call, expenses
against a budget, calendar with notes. Meeting screen has a living animated hero.

**Events** — cover photo or designed cover, speakers, countdown, burning outline,
RSVP, duties (with bot notices), cost and payments, gallery, programme, in-app chat or a
bot-managed Telegram chat, pin to the main page, picture/PDF export.

**Live & reminders** — LIVE badge (pulsing, outline kept) while an event/meeting is on;
"🔴 LIVE now" bot message at the start (`lib/liveNotice.ts`, `live_notified_at`, skipped if
more than 30 min late). Automatic event reminders per ministry (`groups.event_reminder_hours`,
off by default; checked every 5 min) plus manual reminders. Meeting reminders
(`groups.meeting_reminders`: minutes list, null = [120, 60], [] = off; claimed per time in
`job_runs` as `meeting_remind`) with who serves; meeting animation level off / calm / lively
(`groups.meeting_motion`, per meeting `meetings.motion`);
a ⏳ timer and a slow pulse in the last 2 hours (`SoonTimer`, `SoonPulse`).

**Posts & home** — posts with photos, blocks, types, looks, reactions, comments, resend;
home tiles (drag to reorder, expand), several meetings of a day share one tile.

**Money** — income / expense / donation, receipts, dues, voiding, meeting & event money,
PDF/Excel reports delivered by the bot, statistics.

**Phone** — "Add to home screen" (Telegram `addToHomeScreen`; icon = the bot's profile photo,
set from church settings via `setMyProfilePhoto`, `PUT /api/church/bot-photo`), dynamic `/manifest.webmanifest` + `/apple-touch-icon.png` from the church
logo. Phone notifications = bot messages (Telegram push).

**Developer** — Telemetry screen and the Instructions screen (`screens/Guide.tsx`,
content in `lib/guide.ts`): update the guide whenever a feature is added or changed.
